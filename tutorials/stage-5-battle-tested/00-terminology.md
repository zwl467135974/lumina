# 第五阶术语卡：所有硬词的一句话人话

> **怎么用**：读正文前花 5 分钟扫一遍"主线概念"；读到陌生词随时回来查。
> 每篇开头的 🧭 概念卡只列该篇主线，这张卡是全阶汇总，按主题分组。

## 安全与攻防（S01 / S03 / S05 / S06）

| 术语 | 一句话人话 | 出自 |
|---|---|---|
| **fail-closed** | 一切不确定的情况一律按拒绝处理；反面 fail-open（不确定就放行）在安全管线里等于没有管线 | S01 |
| **allow-once** | 审批只对当次调用生效，不是"批准过就永久有效" | S01 |
| **吸收态 / 单调性** | "拒绝"一旦发生，任何后续组件都无法把它翻回"允许"——决定流只能单向滑向拒绝 | S01 |
| **策略否决 ≠ 工具故障** | 安全拒绝不是失败，不能计入熔断统计，否则安全机制会误伤可用性 | S01 |
| **熔断器** | 统计失败次数、失败太多就暂时停用调用的保护组件（详见第三阶 13） | S01 |
| **责任链模式** | 请求沿一条处理器链逐站传递，每站都可以拦截——管线骨架 | S01 |
| **SSRF** | 骗服务器替你访问它够得着、而你够不着的内网 | S03 |
| **DNS rebinding** | 让域名在两次解析时返回不同 IP 的攻击手法——校验时给公网 IP，连接时给内网 IP | S03 |
| **TOCTOU** | Time-of-check to time-of-use：检查的时刻和使用的时刻之间，世界变了 | S03 |
| **连接时校验** | 把校验挂进 HTTP 客户端建连那一刻用的 DNS 解析器——检查和使用收敛成同一次解析 | S03 |
| **重定向跟随** | HTTP 客户端自动跟着 302 跳转走——绕过"只校验首个 URL"的后门 | S03 |
| **授权码（code）** | 第三方登录流程里在浏览器地址栏旅行的一次性兑换券 | S05 |
| **state** | 出发前埋下的随机暗号，防"伪造的回程"，单次有效、取出即删 | S05 |
| **PKCE** | 哈希上路（challenge）、原文留守（verifier）——券被截了也兑不了 | S05 |
| **client_secret** | 应用级密钥，兑换必须服务器对服务器私下进行，绝不进 URL 和前端 | S05 |
| **CSRF** | 用受害者的浏览器伪造"它本人发起"的请求；OAuth2 里表现为用攻击者的 code 给受害者登录 | S05 |
| **提示注入** | 攻击者把"指令"夹带进模型读的"数据"里——利用模型无法从语法上区分二者 | S06 |
| **注入面** | 纸条递进上下文的所有渠道：用户输入、知识库、技能、外部 Agent 返回、网页结果 | S06 |
| **休眠注入** | 静态扫描时无害、条件满足才发作的注入文本（"如果用户问到报表，就……"） | S06 |
| **纵深防御** | 多层防线各自覆盖不同的失效模式——不是重复上锁，是给不同的攻击路径各配一把锁 | S06 |
| **威胁模型** | 你假设防的是谁——"模型被诱导"和"任意恶意代码"是两道完全不同的题 | S06/S08 |

## 分布式与系统（S04 / S07 / S01）

| 术语 | 一句话人话 | 出自 |
|---|---|---|
| **单实例假设** | 代码隐含"世界上只有一个我"——部署拓扑一变，正确的代码变错的 | S04 |
| **心跳判活** | 实例定期续期一个带 TTL 的键：键在=活着，键过期=死亡宣告（不需要死者配合） | S04 |
| **TTL（过期时间）** | 数据的保质期，到点自动消失（Redis 键、DNS 记录都讲这个） | S03/S04 |
| **fail-safe 取舍** | 判活失败按"活着"处理：误杀不可逆，晚回收可兜底——宁漏勿错 | S04 |
| **状态收敛时间** | 系统从不一致到一致的耗时——它和"任务执行时间"是两个不同的 SLA | S04 |
| **ThreadLocal** | 每线程私有的储物柜（工牌）：进公司领牌，安检门看牌 | S07 |
| **换线程 = 丢工牌** | 上下文不随任务跨线程，跨线程必须显式传值 | S07 |
| **TransmittableThreadLocal** | 阿里开源的上下文传递库——注意别和 TTL"过期时间"混淆，正文用全名 | S07 |
| **Sink 接缝** | 接口定义在使用方（core）、实现在提供方（business）的架构接缝，依赖方向不破 | S07 |
| **依赖倒置** | 依赖抽象接口而非具体实现，让"谁离不开谁"的方向不违反分层 | S07 |
| **豁免表（ALWAYS_IGNORE）** | 显式声明某表不参与租户隔离——每一次使用都应该有书面理由 | S07 |
| **ADR（架构决策记录）** | 写下"为什么这么做、代价是什么、什么时候重新评估"的文档 | S08 |
| **SLO** | 服务等级目标——"出事时多快有人知道"的正式承诺 | S08 |

## AI 与上下文工程（S02 / S06）

| 术语 | 一句话人话 | 出自 |
|---|---|---|
| **Token** | LLM 计费与计量的最小单位；CJK 约 1 字 1 token，英文约 4 字符 1 token | S02 |
| **上下文窗口** | 模型一次能读的最大 token 数——装不下就要裁剪 | S02 |
| **预算装填** | 按 token 预算从最新到最旧装历史，装不下就停（break 不是 continue） | S02 |
| **两级压缩** | 第一级确定性修剪（毫秒、零成本、兜底）+ 第二级 LLM 摘要（秒级、保语义） | S02 |
| **溢出自愈** | 估算偏低导致超窗时，确定性紧急压缩后重试——估算不需要精确，需要兜底 | S02 |
| **前缀缓存（KV Cache）** | 请求开头逐字节稳定则服务商打折（不重算注意力矩阵）——摘要格式稳定的意义所在 | S02 |
| **收缩硬保证** | 摘要必须比原文短，否则重试——防止"越摘越长"的保险丝 | S02 |
| **Plan-Execute** | 先让模型拆任务、再逐个执行的 Agent 模式（见 [B02](../stage-4-ai-agent/B02-plan-execute-pattern.md)） | S02 |
| **否决记录** | 拦下 AI/同事方案的理由+替代方案——"驾驶员身份"的唯一证据 | S08 |
