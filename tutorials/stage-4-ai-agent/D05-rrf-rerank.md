## 这节解决什么问题

混合检索出了两路结果——向量路 5 条、关键词路 5 条。怎么合并成一份？有些结果两路都命中了（排名不同），怎么处理？

**RRF 算法**负责融合，**Reranker** 负责重排序精排。

---

## RRF（Reciprocal Rank Fusion）

### 类比：选秀节目综合排名

选手 A 在导师 1 那排第 1，在导师 2 那排第 5。选手 B 在导师 1 排第 3，在导师 2 排第 2。谁综合更强？

RRF 的算法很简单——**分数 = Σ 1/(排名+常数)**：

```
选手 A: 1/(1+60) + 1/(5+60) = 0.0164 + 0.0154 = 0.0318
选手 B: 1/(3+60) + 1/(2+60) = 0.0159 + 0.0161 = 0.0320

选手 B 综合分更高（因为在两路都不错，而 A 虽然第一路第一但第二路很后）
```

### 为什么用 RRF

- **简单**——不用调权重，纯靠排名
- **公平**——两路"话语权"相同
- **效果好**——两路都命中的结果会排前面

> 公式里的常数 60 是论文推荐值，可以调。

## Reranker：精排

### 问题

RRF 融合后的排序还是基于"检索分数"的粗排。有时候检索分数高但**和问题实际相关性不高**。

### Reranker 解决

Reranker 是一个专门的**重排序模型**——它看"问题 + 文档内容"判断真实相关性，重新排序：

```
RRF 粗排后的 Top 5:
  1. 分数 0.95 但实际相关性一般
  2. 分数 0.88 相关性好
  ...

Reranker 精排后:
  1. （原第2条）真正最相关
  2. （原第1条）次相关
  ...
```

### Lumina 的三种 Reranker

```yaml
lumina:
  rag:
    rerank:
      provider: siliconflow    # siliconflow / local / none
```

| Provider | 说明 |
|----------|------|
| **siliconflow** | 免费 API，调用 BAAI/bge-reranker 模型 |
| **local** | 本地部署的重排序模型服务 |
| **none** | 不用 Reranker（只 RRF 融合） |

## 小结

| 概念 | 一句话记忆 |
|------|-----------|
| RRF | 按排名融合（1/(rank+60)），不用调权重 |
| Reranker | 重排序模型，精排粗排结果 |
| 粗排 vs 精排 | 检索分数（粗）→ Reranker（精） |

## 自测题

1. **RRF 为什么用 1/(rank+60) 而不是简单平均分数？**
   <details><summary>答案</summary>不同检索路的分数量纲不同（向量余弦 vs 关键词 BM25），直接平均没意义。RRF 只用排名（1st/2nd），无量纲问题。</details>

2. **Reranker 和向量检索有什么区别？**
   <details><summary>答案</summary>向量检索是"问题向量 vs 文档向量"的相似度（粗排）。Reranker 是"问题+文档"一起输入模型，判断真实相关性（精排）。Reranker 更准但更慢。</details>
