# 推理链可观测性实施方案

> **目标**：让 Agent 每一步推理/工具调用/RAG 检索/记忆注入都可见、可追溯、可量化。
>
> 这是后续所有 AI 深化方向的前提——"你无法改进你看不见的东西"。

---

## 为什么要做这个

### 当前痛点

用户反馈"AI 答错了"，你**没有任何手段定位问题**：
- 是 RAG 没召回相关文档？还是召回了但 Prompt 没用好？
- 是工具调错了？还是工具返回了但推理错了？
- 是上下文太长关键信息被裁了？还是模型本身能力不够？

**日志只有"执行完成"，没有"每一步发生了什么"**。

### 做完之后

```
用户反馈"答错了"
  ↓
打开该次执行的 Trace 树
  ├── [检索] 查"请假流程" → 召回 5 个片段，最高分 0.72（偏低）
  ├── [记忆] 注入 3 条长期记忆 + 12 条历史消息
  ├── [推理] 第 1 轮：思考"需要查 OA 文档"（耗时 2.1s）
  ├── [工具] 调用 webSearch("OA请假流程") → 返回结果（耗时 1.3s）
  ├── [推理] 第 2 轮：基于工具结果生成回答（耗时 3.5s）
  └── [结果] "请假需要在 OA 系统提交..."（总 Token 2340，成本 ¥0.023）

10 分钟定位：检索分数偏低 → 分块策略需优化
```

---

## 设计原则

1. **非侵入**——不改 ReAct 执行逻辑，用 AgentScope Hook 机制旁路采集
2. **异步落库**——trace 写入不阻塞流式输出主路径
3. **成本可归因**——每一步的 Token 消耗独立记录（从任务级到步骤级）
4. **复用现有**——StreamChunk / ToolInvocationRecorder / Micrometer 已有基础

## 埋点方案

### 核心机制：AgentScope Hook

**发现**：AgentScope 1.0.7 的 `ReActAgent.Builder` 支持 `.hook(Hook)` 注册，能拦截全部 9 种事件。**但 Lumina 全项目目前未使用此机制**——这是最大的空白区，也是拦截"单步推理/单步工具调用"的唯一干净通道。

### TraceContext + TraceHook

```java
/**
 * 单次执行的 Trace 上下文（贯穿整个执行链路）
 */
public class TraceContext {
    private String traceUuid;
    private String agentName;
    private String agentType;
    private long startTime;
    private final List<TraceStep> steps = Collections.synchronizedList(new ArrayList<>());
    private final AtomicInteger seqCounter = new AtomicInteger(0);

    // 累积 Token
    private int totalPromptTokens;
    private int totalCompletionTokens;

    public TraceStep newStep(String type, String name) {
        TraceStep step = new TraceStep();
        step.setSeq(seqCounter.incrementAndGet());
        step.setType(type);
        step.setName(name);
        step.setStartTime(System.currentTimeMillis());
        return step;
    }

    public void addStep(TraceStep step) {
        steps.add(step);
        if (step.getPromptTokens() != null) totalPromptTokens += step.getPromptTokens();
        if (step.getCompletionTokens() != null) totalCompletionTokens += step.getCompletionTokens();
    }
}
```

```java
/**
 * AgentScope Hook 实现——拦截 ReAct 每一步
 */
public class TraceHook implements Hook {
    private final TraceContext traceContext;

    public TraceHook(TraceContext traceContext) {
        this.traceContext = traceContext;
    }

    @Override
    public <T> Mono<T> onEvent(T event) {
        // 按事件类型记录 TraceStep
        if (event instanceof PostReasoningEvent e) {
            // 推理完成：记录输出 + 本轮 Token
            TraceStep step = traceContext.newStep("REASONING", "推理");
            step.setOutput(e.getReasoningMessage().getTextContent());
            step.setPromptTokens(e.getReasoningMessage().getChatUsage().getInputTokens());
            step.setCompletionTokens(e.getReasoningMessage().getChatUsage().getOutputTokens());
            step.setDurationMs(System.currentTimeMillis() - step.getStartTime());
            traceContext.addStep(step);
        } else if (event instanceof PostActingEvent e) {
            // 工具调用完成：记录工具名 + 参数 + 返回值
            TraceStep step = traceContext.newStep("TOOL_CALL",
                "工具: " + e.getToolUse().getName());
            step.setInput(e.getToolUse().getInput().toString());
            step.setOutput(e.getToolResult().getText());
            step.setDurationMs(System.currentTimeMillis() - step.getStartTime());
            traceContext.addStep(step);
        }
        // PreReasoning/PreActing 标记 startTime（配对用）
        return Mono.just(event);
    }
}
```

### 埋点位置（6 处）

| # | 位置 | 文件 | 埋什么 | 实现方式 |
|---|------|------|--------|----------|
| 1 | **Hook 注入** | `DefaultAgentExecutionEngine.java:764`（createReActAgent Builder 链） | 推理/工具每一步 | Builder 加 `.hook(new TraceHook(traceContext))` |
| 2 | **RAG 检索** | `DefaultAgentExecutionEngine.java:923`（buildRagSourcesFlux） | query + 召回结果 + 分数 | 检索后加 step，已有 docs+score 数据现成 |
| 3 | **记忆注入** | `DefaultAgentExecutionEngine.java:387+400`（buildContextMessages） | 长期/短期记忆条数 | 取完记忆后加 step |
| 4 | **执行开始** | `DefaultAgentExecutionEngine.java:176`（executeSyncInternal） | trace root 创建 | 创建 TraceContext |
| 5 | **执行结束** | `DefaultAgentExecutionEngine.java:218`（log 成功处） | trace 完成 + 持久化 | 异步写 agent_trace 表 |
| 6 | **流式结束** | `DefaultAgentExecutionEngine.java:286`（doFinally） | 流式 trace 持久化 | doFinally 里异步写 |

## 异步落库方案

**参照审计日志的模式**（AuditAspect → AuditEvent → MQ/本地 Event → 异步消费写库）：

```
执行过程中
  ↓ TraceContext 累积 steps
执行结束
  ↓
发布 AgentTraceEvent（Spring ApplicationEvent）
  ↓ @Async
AgentTraceEventListener 消费
  ↓
写入 lumina_agent_trace 表
```

**不阻塞主路径**——即使写 trace 失败也不影响 Agent 执行结果。

## 修复的附带 Bug

审计发现 Plan-Execute 流式路径有一个 **Token 丢失 bug**：

```
PlanExecuteAgent.eventToChunk(:289) 不填充 tokenUsage
→ AgentServiceImpl(:440) 的 streamTokenUsage 拿不到 Plan-Execute 的 Token
→ 成本统计遗漏 Plan-Execute 路径
```

**在实现 trace 时一并修复**：Hook 的 `PostCallEvent` 能拿到总 `ChatUsage`，写入 trace 的 `total_tokens`，同时回灌到 StreamChunk。

## 风险与对策

| 风险 | 对策 |
|------|------|
| Hook 影响执行性能 | steps 用 synchronizedList，写入是内存操作（微秒级）；落库是异步 |
| steps JSON 太大 | 每个 document preview 截断 200 字；单条 trace 最大 steps 数限制 100 |
| Plan-Execute 的 Hook 需要多注册 | Planner/Executor/Summarizer 各注册一份 TraceHook，共享同一个 TraceContext |
| 流式路径 trace 写入时机 | `doFinally` 保证无论成功/失败/取消都写入 |
| Hook 未被 AgentScope 正确调用 | 先写单元测试验证 Hook 事件触发（mock ReActAgent） |

---

## 不做什么（明确排除）

- **不做分布式 tracing（OpenTelemetry/Jaeger 级别）**——那是跨服务调用链，我们只做单次 Agent 执行的内部步骤
- **不做实时流式 trace 推送**——trace 在执行完成后查（非实时），避免增加流式复杂度
- **不改 ReAct 执行逻辑**——纯旁路采集，Hook 是只读拦截

## 验收标准

- [ ] 创建 ReAct Agent（带 RAG + 工具），执行后 trace 表有一条记录
- [ ] steps JSON 包含：检索/记忆/至少 1 轮推理/至少 1 次工具调用
- [ ] 每步有 durationMs 和（如适用）prompt/completion tokens
- [ ] Plan-Execute 路径的 token 不再丢失（修复附带 bug）
- [ ] 前端能看到 trace 列表 + 树形/时间线详情
- [ ] trace 写入不阻塞流式输出（异步）
- [ ] 多租户隔离生效（查不到其他租户的 trace）
