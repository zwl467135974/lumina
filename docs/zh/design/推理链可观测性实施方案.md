# 推理链可观测性 + 跨实例记忆共享实施方案（v2 — 基于 AgentScope 2.0）

> **目标**：让 Agent 每一步推理/工具调用/RAG 检索可见、可追溯、可量化；同时实现跨实例记忆共享。
>
> **版本**：v2（基于 AgentScope 2.0 内置能力重写，替代 v1 手写 Hook 方案）
> **更新日期**：2026-07-23

---

## 为什么重写（v1 → v2）

升级 AgentScope 2.0 后发现两个关键事实改变了方案：

### 1. 2.0 内置了 Tracing 机制

```
io.agentscope.core.tracing/
├── Tracer.java                 ← 拦截接口（callAgent/callModel/callTool）
├── TracerRegistry.java         ← 全局注册（一行代码生效）
├── OtelTracingMiddleware.java  ← OpenTelemetry 集成
├── NoopTracer.java             ← 空实现（零开销）
└── telemetry/                  ← OTel 语义属性 + 消息模型
```

v1 方案要**手写 Hook + 手写 TraceContext + 手写 6 处埋点**。v2 只需**实现 Tracer 接口 + 一行注册**——工作量砍掉 70%。

### 2. 2.0 的记忆架构支持 AgentStateStore

```
2.0 记忆架构:
  AgentStateStore（接口）── save/get/delete by (userId, sessionId)
    ├── InMemoryAgentStateStore  ← 默认（单机内存）
    ├── JsonFileAgentStateStore  ← 文件
    └── ← Lumina 实现这里: RedisAgentStateStore（跨实例共享）

  StateBackedMemory ── 把 AgentStateStore 桥接成 Memory 接口
    └── addMessage/getMessages（操作 AgentState.context）
```

v1 方案中 Lumina 的 MemoryManager 是**独立于 AgentScope 的旁路记忆**（自己管 Redis 存取 + context 注入）。v2 改为**适配成 AgentScope 原生 AgentStateStore**——Agent 的记忆由 SDK 统一管理，天然支持跨实例。

## Part 1：推理链可观测性

### 方案：实现 Tracer 接口 + 全局注册

#### Tracer 接口（4 个拦截点）

```java
// 2.0 内置接口（反编译确认）
public interface Tracer {
    // 拦截 Agent 调用（一次完整的 ReAct 循环）
    default Mono<Msg> callAgent(AgentBase agent, List<Msg> inputs, Supplier<Mono<Msg>> next);

    // 拦截 LLM 调用（每轮 Reason）
    default Flux<ChatResponse> callModel(ChatModelBase model, List<Msg> inputs,
                                         List<ToolSchema> tools, GenerateOptions options,
                                         Supplier<Flux<ChatResponse>> next);

    // 拦截工具调用（每轮 Act）
    default Mono<ToolResultBlock> callTool(Toolkit toolkit, ToolCallParam param,
                                           Supplier<Mono<ToolResultBlock>> next);

    // 拦截格式化（Formatter）
    default <TReq, TResp, TParams> List<TReq> callFormat(
        AbstractBaseFormatter<TReq, TResp, TParams> formatter, List<Msg> inputs,
        Supplier<List<TReq>> next);
}
```

**设计**：每个方法都是"装饰器"——`next` 是原始调用，你可以在 `next.get()` 前后插入采集逻辑。

#### LuminaTraceTracer 实现

```java
package io.lumina.agent.tracing;

/**
 * Lumina 推理链 Tracer 实现
 *
 * <p>通过 TracerRegistry.register() 全局注册，拦截 AgentScope 所有 Agent/Model/Tool 调用。
 * 不需要改任何 Builder 代码——一行注册全局生效。
 */
public class LuminaTraceTracer implements Tracer {

    private final TraceCollector collector;    // 采集器（收集 step + 异步落库）

    // === 拦截 Agent 调用（创建 trace root span）===
    @Override
    public Mono<Msg> callAgent(AgentBase agent, List<Msg> inputs, Supplier<Mono<Msg>> next) {
        String traceId = UUID.randomUUID().toString();
        long start = System.currentTimeMillis();
        TraceContext ctx = collector.startTrace(traceId, agent.getName(), inputs);

        return next.get()                          // 执行原始调用
            .doOnSuccess(result -> {
                ctx.setDuration(System.currentTimeMillis() - start);
                ctx.setOutput(result);
                collector.finishTrace(ctx);        // 异步落库
            })
            .doOnError(e -> collector.failTrace(ctx, e))
            // 把 traceId 放入 Reactor Context 供下游 callModel/callTool 读取
            .contextWrite(reactor.util.context.Context.of("traceId", traceId));
    }

    // === 拦截 LLM 调用（每轮 Reason）===
    @Override
    public Flux<ChatResponse> callModel(ChatModelBase model, List<Msg> inputs,
                                        List<ToolSchema> tools, GenerateOptions options,
                                        Supplier<Flux<ChatResponse>> next) {
        long start = System.currentTimeMillis();
        return next.get()
            .doOnNext(response -> {
                // 每个 ChatResponse 包含增量 token 信息
                ChatUsage usage = response.getChatUsage();
                if (usage != null) {
                    collector.recordReasoningStep(start, usage);
                }
            });
    }

    // === 拦截工具调用（每轮 Act）===
    @Override
    public Mono<ToolResultBlock> callTool(Toolkit toolkit, ToolCallParam param,
                                          Supplier<Mono<ToolResultBlock>> next) {
        long start = System.currentTimeMillis();
        String toolName = param.getInput().keySet().iterator().next();  // 工具名

        return next.get()
            .doOnSuccess(result -> {
                collector.recordToolStep(toolName, param.getInput(), result,
                    System.currentTimeMillis() - start);
            });
    }
}
```

#### 全局注册（一行代码）

```java
@Component
public class TraceConfig {
    @PostConstruct
    public void init() {
        // 全局注册——所有 ReActAgent 自动被拦截
        TracerRegistry.register(new LuminaTraceTracer(traceCollector));
    }
}
```

**和 v1 方案的对比**：v1 要在每个 `ReActAgent.builder()` 链上加 `.hook(TraceHook)`（9 处），v2 只需**一处注册全局生效**。

### TraceCollector + 异步落库

```java
/**
 * Trace 采集器——收集 step + 异步落库
 */
@Component
@RequiredArgsConstructor
public class TraceCollector {

    private final AgentTraceMapper traceMapper;
    private final ObjectMapper objectMapper;

    // 每次执行创建一个上下文（ThreadLocal + Reactor Context 双轨）
    public TraceContext startTrace(String traceId, String agentName, List<Msg> inputs) {
        TraceContext ctx = new TraceContext(traceId, agentName);
        ctx.setInput(inputs);
        return ctx;
    }

    // 记录推理步骤
    public void recordReasoningStep(long startTimestamp, ChatUsage usage) {
        TraceStep step = new TraceStep();
        step.setType("REASONING");
        step.setPromptTokens(usage.getInputTokens());
        step.setCompletionTokens(usage.getOutputTokens());
        step.setDurationMs(System.currentTimeMillis() - startTimestamp);
        // 追加到当前 TraceContext（从 Reactor Context 取）
    }

    // 记录工具调用
    public void recordToolStep(String name, Map<String, Object> input,
                               ToolResultBlock output, long durationMs) {
        TraceStep step = new TraceStep();
        step.setType("TOOL_CALL");
        step.setName("工具: " + name);
        step.setInput(objectMapper.writeValueAsString(input));
        step.setOutput(output.getText());
        step.setDurationMs(durationMs);
    }

    // 异步落库（不阻塞主路径）
    public void finishTrace(TraceContext ctx) {
        CompletableFuture.runAsync(() -> {
            AgentTraceDO trace = buildTraceDO(ctx);
            traceMapper.insert(trace);
        });
    }
}
```

### RAG 检索 + 记忆注入的埋点

Tracer 接口拦截了 Agent/Model/Tool 三层。RAG 检索和记忆注入是 Lumina 自己的逻辑（不在 SDK 内），仍需在现有代码中手动埋点（但比 v1 简单）：

| 位置 | 埋什么 | 实现 |
|------|--------|------|
| `buildRagSourcesFlux`（:923） | RAG 检索 query + 召回结果 | 在 `docs` 拿到后调 `collector.recordRetrievalStep()` |
| `buildContextMessages`（:387/:400） | 记忆注入条数 | 在取完记忆后调 `collector.recordMemoryStep()` |

**只有 2 处手动埋点**（v1 是 6 处），因为 Tracer 自动覆盖了推理和工具调用。

## Part 2：跨实例记忆共享（AgentStateStore）

### 问题

当前 Lumina 的记忆是**旁路管理**：

```
MemoryManager（Lumina 自建）
  ├── Redis 存取对话消息（lumina:agent:memory:{conversationId}）
  ├── buildContextMessages() 手动注入上下文
  └── AgentScope 的 Memory 被忽略（升级时去掉了 .memory()）
```

问题：
1. AgentScope 2.0 的 ReActAgent 有自己的内部状态管理（AgentState），但 Lumina 没接入
2. `InMemoryAgentStateStore` 是单机内存——多实例部署时实例 A 的记忆实例 B 看不到
3. MemoryManager 的记忆和 AgentScope 的 AgentState 是两套独立系统，可能冲突

### 方案：实现 RedisAgentStateStore

```java
package io.lumina.agent.memory;

/**
 * 基于 Redis 的 AgentStateStore——跨实例共享 Agent 状态
 *
 * <p>AgentScope 2.0 的 AgentState 有 toJson()/fromJsonString()，
 * 直接存到 Redis，任何实例都能读取。
 */
@Component
@RequiredArgsConstructor
public class RedisAgentStateStore implements AgentStateStore {

    private final RedisCacheManager redisCacheManager;
    private static final String KEY_PREFIX = "lumina:agent:state:";
    private static final Duration TTL = Duration.ofDays(7);  // 7 天过期

    // 保存状态（key = userId + sessionId）
    @Override
    public void save(String userId, String sessionId, String key, State state) {
        String redisKey = buildKey(userId, sessionId, key);
        String json = ((AgentState) state).toJson();
        redisCacheManager.set(redisKey, json, TTL);
    }

    // 读取状态
    @Override
    public <T extends State> Optional<T> get(String userId, String sessionId,
                                              String key, Class<T> type) {
        String redisKey = buildKey(userId, sessionId, key);
        String json = redisCacheManager.get(redisKey);
        if (json == null) return Optional.empty();
        return Optional.of(type.cast(AgentState.fromJsonString(json)));
    }

    // 批量保存（用于 context 列表）
    @Override
    public void save(String userId, String sessionId, String key,
                     List<? extends State> states) {
        // AgentState 的 context 是 List<Msg>，整条 AgentState 一起存
        // （AgentState.toJson() 包含完整 context）
    }

    // ... delete / exists / listSessionIds / getList 等方法类似
}
```

### 接入方式

```java
// DefaultAgentExecutionEngine 创建 Agent 时
ReActAgent agent = ReActAgent.builder()
    .name(config.getAgentName())
    .model(model)
    .toolkit(toolkit)
    .stateStore(redisAgentStateStore)   // ← 注入 Redis 状态后端
    .defaultSessionId(conversationId)   // ← 会话 ID
    .build();
```

**效果**：
- 实例 A 执行 Agent → SDK 自动 save 到 Redis
- 实例 B 执行同一会话 → SDK 自动 load 从 Redis → 看到完整上下文
- **跨实例记忆共享，零额外代码**

### MemoryManager 的角色变化

```
升级前（旁路管理）:
  MemoryManager 独立管 Redis 对话消息
  + 手动 buildContextMessages 注入
  + AgentScope Memory 被忽略

升级后（适配层）:
  RedisAgentStateStore 实现 AgentStateStore 接口
  + AgentScope SDK 自动管理记忆（save/load via stateStore）
  + MemoryManager 退化为"长期记忆"管理（ReflectiveMemory 不变）
  + buildContextMessages 仍负责注入 RAG + 长期记忆
```

**短期记忆**（对话历史）由 AgentScope 2.0 + RedisAgentStateStore 自动管理。
**长期记忆**（ReflectiveMemory 提取的事实）仍由 Lumina 的 MemoryManager 管理。

### 渐进式迁移策略

不要一次性替换，分两步：

**Step 1（本次）**：实现 RedisAgentStateStore + 注入到 Builder
- AgentScope 的 AgentState 会自动 save/load（但 Lumina 的 buildContextMessages 暂时还手动注入）
- 两套记忆并存，但都走 Redis，数据不冲突

**Step 2（后续）**：让 buildContextMessages 读 AgentStateStore 而非 MemoryManager
- 完全统一到 AgentScope 的记忆体系
- MemoryManager 只管长期记忆

## 风险与对策

| 风险 | 对策 |
|------|------|
| Tracer 全局注册影响所有 Agent | 性能可控（采集是内存操作，落库异步）；NoopTracer 作为关闭开关 |
| Reactor Context 传递 traceId | callAgent 的 contextWrite 注入；下游用 deferContextual 读取 |
| AgentStateStore 序列化兼容 | AgentState.toJson/fromJsonString 是 SDK 内置，自动处理 Msg 序列化 |
| 两套记忆并存的数据一致性 | Step 1 不删除 MemoryManager，让 SDK 和 MemoryManager 都走 Redis（key 不同） |
| RedisAgentStateStore 的 getList 性能 | AgentState 整体存储（不拆分 Msg），一次 GET 拿全量 |

## 验收标准

### 推理链 Trace
- [ ] 创建 ReAct Agent（带 RAG + 工具），执行后 trace 表有记录
- [ ] steps JSON 包含：检索/记忆/推理/工具调用
- [ ] 每步有 durationMs 和 Token
- [ ] trace 写入不阻塞流式输出（异步）
- [ ] 前端能看到 trace 列表 + 树形详情

### 跨实例记忆
- [ ] RedisAgentStateStore 注册后，Agent 执行后 Redis 有 state 数据
- [ ] 同一会话连续两次执行，第二次能看到第一次的上下文
- [ ] 多实例部署时，实例 A 的会话在实例 B 可续（后续验证）

## 不做什么

- **不做 OpenTelemetry/Jaeger 分布式 tracing**——2.0 的 OtelTracingMiddleware 可以后续启用，本次先做 Lumina 自己的 trace 表 + 前端可视化
- **不删除 MemoryManager**——渐进式迁移，Step 2 再统一
- **不做实时流式 trace 推送**——trace 在执行完成后查
