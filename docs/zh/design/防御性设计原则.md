# 防御性设计原则（确定性优先）

> 来源：v3.11 融合 DeepSeek Harness 的设计审查。原则：**能确定性解决的，不过 LLM；
> 能在源头校验的，不留给下游兜底；能事件化的观测，不侵入引擎。**

## 一、确定性优先（免模型防线）

新增任何"智能"防护/处理前，先问：**能不能用规则确定性解决？** 规则防线的优势是
零成本、零幻觉、可测试、可审计。LLM 只用于真正需要理解语义的环节。

lumina 已落地的确定性防线（新防护请挂靠同类机制）：

| 防线 | 机制 | 位置 |
|---|---|---|
| 输入注入检测 | 11 种正则模式 | `PromptInjectionFilter` |
| 上下文第一级压缩 | 超长消息 head/tail 确定性修剪 | `ContextPruner`（A2） |
| 溢出紧急压缩 | 保留头尾 + 中段修剪，不调 LLM | `DefaultAgentExecutionEngine#emergencyCompact`（A2） |
| 摘要收缩硬保证 | 估算 token 比较，超出截断/放弃 | `ContextSummarizerImpl#enforceShrink`（A2） |
| 工具结果外存化 | 超阈值全文存档 + 预览替换 | `ToolResultSpiller`（A5） |
| 工具策略异常 | 任一拦截器/守卫/审批异常按拒绝 | `ToolSecurityPipeline`（A4） |

## 二、fail-closed 融入词表而非约定

失败语义写进类型/词表，不依赖调用方自觉：

- 审批结果只有 `boolean`，无端口/异常/超时/拒绝一律 `false`（`ToolApprovalPort`）。
- 单调守卫 `ToolGuard` 没有 allow 臂——返回 null 弃权或非 null 否决，
  拒绝在数学上不可被其他策略翻转。
- 任务中断状态 `INTERRUPTED` 与 `FAILED`/`CANCELLED` 是不同词——
  "结果未知"不是"失败"，对用户和模型的行动建议不同（仅幂等操作可安全重试）。

## 三、中断即事实（合成闭合）

中断/崩溃不掩盖、不静默丢弃，产出可行动的信息：

- SSE 中断：部分回复落库 + `[本次响应因中断未完成]` 标记（A3）。
- 服务重启：RUNNING 任务标记 `INTERRUPTED` + 结果未知提示（B4，`AgentTaskStartupReconciler`）。
- 摘要失败：降级为确定性修剪，绝不回退"全量加载"（可能更糟）。

## 四、观测走事件，不走侵入

引擎只发布事实（`AgentTurnEvent`：STARTED/COMPLETED/FAILED/INTERRUPTED），
指标/审计/计费/告警作为消费者各自订阅。新增观测需求 = 新增一个 `@EventListener`，
而不是改引擎。

## 五、委派只能收紧（权限冻结）

子 Agent 的能力边界在启动时快照，且只能是父 Agent 的子集：
工具白名单取交集，交集为空即空工具集（空白名单的"注册全部工具"语义
不适用于委派场景）。委派不能提权，超界即汇报。
