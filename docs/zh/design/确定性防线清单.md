# 确定性防线清单（B3）与中断语义边界（B4）

> v3.14 批次 4.3 · DSH B3/B4 收口 · 本文回答两个问题：
> ① 哪些安全/资源保证是**代码强制的**（构造性，提示注入不可绕过），哪些只是**提示词约定**（建议性，模型可违反）；
> ② A6 真取消（v3.11）在中断路径上的**边界情况**——什么有保证、什么是尽力而为。

## 一、确定性防线清单（B3）

原则：**安全属性必须落在代码强制层；提示词层只做行为引导，永不承担安全职责。**
"提示注入能否绕过 X" 的判定标准 = X 在下表哪一层。

### 代码强制（构造性，注入不可绕过）

| # | 防线 | 机制 | 拒绝语义 |
|---|------|------|---------|
| 1 | 工具 DENY 名单/拦截器 | `ToolSecurityPipeline` 拦截器链（`ConfigToolInterceptor` 等） | DENY 立即返回，理由对模型可见；可被 YOLO 降级的只有 ASK |
| 2 | 单调守卫 | `ToolGuard`（审批之后求值，只有 deny 臂） | 任何模式、任何审批结果都翻不过 |
| 3 | 人工审批（fail-closed） | `ToolApprovalPort` 无实现/异常 → 拒绝 | 宁可拒绝不误放 |
| 4 | 会话模式 PLAN | `SessionModeInterceptor`（`isProvablyReadOnly` 纯判定，不受豁免开关影响） | 非只读调用构造性阻断 |
| 5 | Explore 型工具面 | 注册期过滤（白名单 ∩ 只读集）+ 强制 PLAN 双防线 | 写工具根本不注册；运行期逐调用再拦 |
| 6 | 生命周期钩子 PreToolUse | `AgentHookInvoker`（安全管线之前） | DENY 阻断；超时/异常**中立放行**（fail-open，见边界注记①） |
| 7 | 自主编排沙箱 | GraalJS 无宿主访问/无 IO；四重限额（总量/并发/单次/超时）触顶 fatal；危险属性名物化拒绝 | 拼错选项/触顶不溶进普通失败 |
| 8 | artifact.report 契约 | type 白名单 + 64KB 上限 + fail-fast；**报告不进模型上下文** | 呈现面不可能变成数据外流通道 |
| 9 | 上下文预算 | `TokenEstimator` 装填历史（宁可少带绝不超窗）；spill 预览含提示行也必须 ≤ 阈值 | 物理上无法撑爆窗口 |
| 10 | 大消息外存 | `HistorySpiller` 存档失败保留原文（宁可贵不失真）；取回工具结果不再 spill（防回环） | 无丢失语义 |
| 11 | 超时与熔断 | 工具执行超时（ERROR 结果）；熔断打开即拒 | 资源故障不出无限等待 |
| 12 | Stop/转向续跑预算 | 每回合共享上限（默认 3 段），达上限强制结束 | "继续"不可能无限烧 Token |
| 13 | 审计可见 | 阻断路径（DENY/CONTINUE/PLAN 拒绝）带理由与来源日志 + `agent.hook.invocation` 指标 | 拒绝必留痕 |

### 提示词约定（建议性——模型可被诱导违反，升级需下沉到代码层）

| 约定 | 现状 | 风险与升级路径 |
|------|------|--------------|
| 系统提示中的角色/边界描述（"不要泄露配置"等） | 仅引导 | 敏感数据出口应加输出护栏（guardrail，已有开关）或 PreToolUse 钩子审计 |
| 图片引用标记的解释（"如需查看请让用户重新提供"） | 仅引导 | 模型谎称已看图无害（拿不到本体）；引擎侧无图片回放通道即事实保证 |
| 会话开始上下文/技能目录注入的"不要逐条复述" | 仅引导 | 无安全影响，纯 token 经济 |
| browser-control 技能的操作纪律（快照→ref→操作） | 技能文本 | 浏览器行为边界由 MCP server 参数（--isolated/--blocked-origins）承担，见接入指南 |
| 转向指令优先级声明（"优先级高于原任务"） | 引导文本 | 转向来源是已鉴权 API；模型不遵从只是效果打折，无安全边界 |

> 边界注记①：钩子超时/异常的中立放行是**可用性优先**的显式决策（钩子故障不瘫痪平台）。
> 强一致合规门必须在钩子实现内自行捕获故障并显式返回 deny——这是接口契约（见《生命周期 Hook 接入指南》）。

## 二、中断语义边界（B4，A6 真取消收口）

### 有保证的（代码强制）

| 保证 | 机制 |
|------|------|
| 三种流式终态（完成/取消/错误）都闭合记忆 | `buildAgentStreamFlux` 终态处理：`doOnComplete`/`doOnCancel`/`onErrorResume` 均落记忆，已生成部分不丢 |
| 中断标记不可伪造遗漏 | 中断路径追加 `INTERRUPTED_RESPONSE_MARKER`（"内容可能不完整"），下一轮模型可见上轮不完整 |
| 取消时上下文清理 | `doFinally` 清 conversationId/sessionMode（含并行流） |
| 工具超时必返回 | 适配器 `timeout()` → ERROR 结果（带参数 schema 提示供自纠） |

### 尽力而为的（明确不是保证）

| 边界情况 | 实际语义 |
|---------|---------|
| 取消时正在执行的工具调用 | 取消信号不进入工具线程——工具跑完被丢弃（结果不进任何上下文）。副作用已发生（如已发出的外部写），平台不回滚 |
| 超时后的工具线程 | 协作式放弃（结果丢弃），线程可能仍在跑至自然结束——卡死实现不会阻塞回合，但进程内资源占用至其退出 |
| 取消瞬间的记忆一致性 | `finalResponse` 累积到取消点为止；正在流式中的半句会入库（带中断标记）——这是"合成闭合"设计选择：留半句优于孤儿记录 |
| 续跑段中途取消 | 段循环对终端透明：取消作用于整条组合流，已完成的段产出已闭合；未开始段不再执行；续跑预算中未用部分作废 |
| 转向消息在取消后的去向 | 未消费的队列消息保留，下一回合入口消费——取消不清空转向队列（用户意图不因取消丢失） |
| 同步路径无取消 | `executeSync` 阻塞至完成/失败/超时；中断手段只有进程级（这是同步 API 的固有语义） |
| 审批等待中的工作流 | `HumanApprovalRequiredException` 暂停（PAUSED），实例状态持久化——恢复时从中断节点继续，非重跑 |

### 与上游（ZCode/DSH）的差异说明

ZCode 的 true-cancel 走进程树终止（SIGKILL 子进程）；Lumina 工具是**进程内调用**，
无进程边界可杀——"真取消"落在**流切断 + 记忆闭合 + 上下文清理**三层，
工具线程本身不强制终止（JVM 线程 stop 已废弃）。若引入可执行外部进程的工具
（如浏览器子进程），其生命周期管理需单独设计（当前由 MCP server 自身承担）。
