# Lumina v3.0.0 路线图 — 稳定化与生产就绪

> **核心目标：** 从"功能堆叠"升级为"真实可用、生产级别"。不新增功能，聚焦稳定性、体验、完整性和端到端验证。

---

## 背景与动机

v2.0.0 完成了 P0-P5 + E1/E3/E4/E5 功能交付，但存在以下系统性问题：

- **端到端跑不通**：多台电脑实测发现需要大量修复才能启动（Redis 密码、Gateway 过滤器命名、MyBatis 拦截器冲突等）
- **前端 demo 级质量**：页面能渲染但交互不完整、i18n 不工作、暗色主题破碎、无响应式
- **权限体系断层**：新功能模块无权限种子数据，非超管用户无法使用
- **数据层不一致**：DB 字段名与前端类型不匹配、Agent 配置无法持久化
- **无种子数据**：系统初始化后为空白，无法验证功能

v3.0 的衡量标准不是"有多少功能"，而是"每个功能是否真正可用"。

## 问题清单（按优先级）

### P0 — 阻塞性问题

> 不修复这些问题，系统核心链路无法正常使用。

| # | 问题 | 影响 | 修复方案 | 涉及文件 |
|---|------|------|----------|----------|
| 1 | **i18n 完全不工作** | 所有页面硬编码中文，切换英文只翻译 2 个菜单项 | 为所有页面补全 `$t()` 调用 + 扩充翻译文件至 300+ key | 全部 `views/**/*.vue` + `locales/zh-CN.ts` + `locales/en.ts` |
| 2 | **新功能无权限种子数据** | V2 只初始化 `system:*` 权限，Agent/工作流/知识库/评估/成本等模块无权限，非超管用户看不到菜单 | Flyway V17 补充各模块 CRUD 权限 + 角色分配 + 菜单种子数据 | `V17__add_module_permissions.sql` |
| 3 | **`lumina_agent` 表缺字段** | 前端表单保存 `llmConfig`/`tools` 但 DB 无对应列 | Flyway V18 增加 `llm_config TEXT` + `tools VARCHAR(500)` 列 | `V18__add_agent_config_columns.sql` + `AgentDO.java` |
| 4 | **字段名不匹配** | DB `real_name` vs 前端 `nickname`；DB `contact_name/contact_phone/contact_email` vs 前端 `contact/phone/email` | 统一为前端字段名（修改 DB 列名或前端类型映射） | `V1__init_schema.sql` 对应实体 + `types/api.ts` |

## 实施阶段

**目标：DB schema 与前端类型完全对齐，权限/种子数据覆盖所有模块。**

| V17 补充种子数据 | 示例 Agent 2 个 + 示例 Prompt 3 个 + 示例工作流 1 个 |
