# 工作流设计指南

## 概述

Lumina 工作流引擎通过 DAG（有向无环图）编排实现多 Agent 协作。支持 YAML 定义或可视化设计器。

## 工作流引擎说明

Lumina v3.1+ 使用 **Flowable 7.0** 作为工作流执行引擎（`@Primary`），原自研 `DefaultWorkflowEngine` 保留为 fallback。

### 架构
- 前端设计器输出 YAML 格式不变
- 后端 `FlowableBpmnConverter` 将 YAML 转换为 BPMN 模型
- Flowable 负责状态管理、并行网关、多实例循环
- 自定义 ServiceTask Delegate 处理 AI 特有节点（Agent/Transform/Loop）

### 节点类型映射
| YAML 节点 | BPMN 元素 | Delegate |
|-----------|-----------|----------|
| agent | ServiceTask | AgentServiceTaskDelegate |
| transform | ServiceTask | TransformServiceTaskDelegate |
| loop | ServiceTask | LoopServiceTaskDelegate |
| condition | ExclusiveGateway | - |
| parallel | ParallelGateway | - |
| human | UserTask | - |

## 节点类型

| 类型 | 说明 | 关键属性 |
|------|------|---------|
| `agent` | 执行 Agent | `agentId`、`input`（SpEL 表达式）、`outputVar` |
| `condition` | 条件分支 | `expression`、`trueBranch`、`falseBranch` |
| `loop` | 循环 | `iterations`、`input` |
| `parallel` | 并行执行 | `branches[]`、`waitAll` |
| `transform` | 数据转换 | `transformExpr` 或 `template` |
| `human` | 人工审批 | `decisionVar`、`prompt`、`options` |

## YAML 定义

```yaml
name: "customer-complaint"
description: "客户投诉处理流水线"

inputs:
  - name: complaint
    type: string
    required: true

nodes:
  - id: classify
    type: agent
    name: "意图分类"
    agentId: 1
    input: "#complaint"
    outputVar: category

  - id: route
    type: condition
    expression: "#category.contains('refund')"
    trueBranch: refund-agent
    falseBranch: general-agent

  - id: refund-agent
    type: agent
    name: "退款处理"
    agentId: 2
    input: "#complaint"
    outputVar: result

  - id: general-agent
    type: agent
    name: "通用处理"
    agentId: 3
    input: "#complaint"
    outputVar: result

edges:
  - from: classify
    to: route
  - from: refund-agent
    to: done
  - from: general-agent
    to: done

outputs:
  result: "#result"
```

## 协作模式

### 1. 流水线（Pipeline）
Agent A → Agent B → Agent C，前一个的输出是后一个的输入。

### 2. 主管-工人（Supervisor-Worker）
主管分解任务 → 多个 Worker 并行执行 → 主管汇总结果。

### 3. 路由（Router）
分类 Agent 判断意图 → 路由到不同专业 Agent。

### 4. 辩论（Debate）
正方 Agent 发表观点 → 反方 Agent 反驳 → 裁判 Agent 综合判断。

### 5. 人工介入（Human-in-the-Loop）
Agent 准备材料 → 暂停等待人工审批 → 审批通过后继续执行。

## SpEL 表达式

输入表达式使用 Spring Expression Language：

| 表达式 | 含义 |
|--------|------|
| `#variable` | 引用上下文变量 |
| `'#input + " 后缀"'` | 字符串拼接 |
| `#result.toUpperCase()` | 方法调用 |
| `#category == 'refund'` | 条件判断 |

## 可视化设计器

访问路径：`/workflow/designer`

1. **拖拽节点**：从左侧面板拖到画布
2. **连接节点**：拖拽节点底部圆点到目标节点顶部
3. **编辑属性**：点击节点后在右侧面板编辑
4. **YAML 模式**：切换到 YAML 直接编辑，支持双向同步
5. **保存**：创建或更新工作流定义

## 执行

### 同步执行
```bash
POST /api/v1/workflows/{id}/execute
Body: {"inputs": {"complaint": "我要退款"}}
```

### 流式执行（SSE）
```bash
POST /api/v1/workflows/{id}/execute/stream
# 返回：NODE_STARTED → NODE_COMPLETED → ... → WORKFLOW_COMPLETED
```

### 恢复（人工审批后）
```bash
POST /api/v1/workflows/instances/{instanceId}/resume?decision=approved
```

## 可观测性

- **SSE 进度推送**：实时节点状态
- **多 Agent 对话气泡**：每个 Agent 的结果以气泡形式展示
- **执行日志**：每节点的输入/输出/耗时持久化到数据库
- **Micrometer 指标**：`workflow.execution.duration`、`workflow.node.duration`
