# 只读探索子代理与运行中转向指南

> v3.14 批次 3.2 · 借鉴 ZCode 子代理体系 + steering / DSH B2 · 组件：`DefaultAgentExecutionEngine` / `io.lumina.agent.steering`

## 一、Explore 型只读探索子代理

### 用途

代码库调研、资料检索、只读分析类任务——**构造性只读**：探索型 Agent 从注册面到运行面都无法触发写路径。

### 使用方式

创建 Agent 时 `agentType` 设为 `Explore`（无需新字段，约定即能力）：

```
agentType = "Explore"
tools     = "util.search,util.time,util.math,code.execute"   # 白名单照常配置
```

引擎对 Explore 型做双重防线：

| 防线 | 位置 | 机制 |
|------|------|------|
| 第一道：工具面过滤 | 工具注册期 | 白名单 ∩ 可证明只读集（复用 v3.13 只读分级三层证据：名单/MCP readOnlyHint/code 启发式）——配置误加写工具也不注册 |
| 第二道：PLAN 模式强制 | 运行期 | `effectiveSessionMode` 强制 PLAN——即使请求显式传 YOLO，非只读调用仍被 `SessionModeInterceptor` 构造性阻断且理由对模型可见 |

注：`code.execute` 在注册期以空参数做宽松启发式评估；运行期由 PLAN 模式以真实代码逐调用权威判定（含危险词元的代码被拒）。

### 分类器缺失的退化

无 `ReadOnlyToolClassifier` Bean 时工具面退化为白名单注册，运行期 PLAN 仍逐调用拦截（fail-closed 职责在运行期）——正常部署分类器始终存在，此路径仅极端裁剪场景。

## 二、运行中转向（steering）

### 用途

Agent 执行期间（长任务/多轮工具循环中）向会话投递调整指令，改变后续行为——不必等本轮结束。

### API

```
POST /api/v1/conversations/{conversationId}/steering
{ "message": "优先看支付模块，跳过前端" }
```

消息校验：非空、≤4000 字符（超出截断）。功能未开启时返回失败提示。

### 注入路径（三处消费点，一次性消费）

| 消费点 | 生效时机 | 注入形式 |
|--------|---------|---------|
| **工具结果搭车** | 每次工具调用后（ReAct 循环内，最即时） | 工具结果尾部追加 `[用户运行中转向指令] ...` 标记段，每结果至多一条 |
| **段边界注入** | 流式段完成 / 同步续跑点 | 上一段回答 + `[用户运行中转向指令]` USER 消息并入上下文正规续跑 |
| **执行入口** | 下一回合开始时 | 并入任务描述 |

### 续跑预算

转向触发的续段与 Stop 钩子 continue **共享**每回合预算（`max-segment-continues`，默认 3；steering 未启用时 Stop 用 `hooks.max-stop-continues`）。达上限强制结束回合并告警——用户持续发消息不会无限烧 Token。

### 配置

```yaml
lumina:
  agent:
    steering:
      enabled: true          # 默认 false
      max-message-chars: 4000
      max-segment-continues: 3
```

### 部署边界

默认 `InMemorySteeringMessageStore` 为**单实例语义**：多实例部署下转向请求必须路由到执行实例（网关按 conversationId 会话粘滞）。跨实例场景实现 `SteeringMessageStore` 接口（Redis）并注册为 `@Primary` Bean 覆盖默认实现。

### 与既有机制的关系

- 工具结果搭车位于 spill 外存化**之后**、PostToolUse 钩子**之前**——模型/钩子/调用记录看到一致的最终内容
- 转向消息来自平台 API（已鉴权），以明确标记注入；与提示注入的边界：注入内容不自称系统指令，模型侧标记为用户指令
