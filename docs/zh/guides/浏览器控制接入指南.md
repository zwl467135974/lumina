# 浏览器控制接入指南（Playwright MCP）

> v3.13 路线图批次 1.2 交付物。让 Lumina Agent 获得真实浏览器操作能力：
> 打开网页、读取 JS 渲染内容、表单交互、截图留证。双上游验证方案
> （DeepSeek Harness browser-use 与 ZCode Browser Use 均为 Playwright 路线），
> Lumina 通过现有 MCP 通道接入官方 `@playwright/mcp`，**引擎零改动**。

## 一、架构

```
Lumina Agent 服务
  └── MCP stdio 子进程：npx -y @playwright/mcp@latest
        └── Chromium（--headless --isolated）
```

浏览器子进程与 Agent 服务同主机。工具以 `mcp__playwright__browser_*`
注册进工具管理器，走既有 MCP 健康检查与重连机制。

## 二、前置条件

1. **Node.js ≥ 18 与 npx** 在 Agent 服务主机可用（`node --version` 验证）。
2. **浏览器内核**：首次部署执行
   ```bash
   npx playwright install chromium
   ```
   或使用系统已装的 Chrome/Edge（args 加 `--browser=chrome`，免下载内核）。
3. **Linux 无头环境**需要系统依赖库：`npx playwright install-deps chromium`
   （Debian/Ubuntu；容器部署时写入镜像构建步骤）。

## 三、启用配置

### 方式 A：配置文件（重启生效）

`nacos-config/lumina-agent-service.yaml`（或本地 `application.yml`）打开
`lumina.mcp.enabled` 并加入 server 条目——模板已写在配置文件注释区：

```yaml
lumina:
  mcp:
    enabled: ${MCP_ENABLED:true}
    servers:
      - name: playwright
        transport: stdio
        command: npx
        args:
          - "-y"
          - "@playwright/mcp@latest"
          - "--browser=chromium"
          - "--headless"        # 服务端部署必须无头
          - "--isolated"       # 内存态 profile，不落盘
          - "--blocked-origins=http://127.0.0.1;http://localhost;http://10.*;http://192.168.*"
```

`--blocked-origins` 按部署环境调整（支持通配），用于拦截浏览器对内网与
环回地址的访问；不配置则浏览器可到达主机网络可达的任意目标。

### 方式 B：运行时动态注册（免重启）

```bash
POST /api/v1/mcp/servers
{
  "name": "playwright",
  "transport": "stdio",
  "command": "npx",
  "args": ["-y", "@playwright/mcp@latest", "--browser=chromium", "--headless", "--isolated"]
}
```

### 验证

```bash
GET /api/v1/mcp/servers   # playwright 状态应为 CONNECTED
GET /api/v1/mcp/tools     # 应列出 mcp__playwright__browser_navigate 等工具
```

## 四、导入配套技能

技能资产随仓库分发：[docs/skills/browser-control/SKILL.md](../../skills/browser-control/SKILL.md)。

前端「技能管理」页 → 导入 → 上传该文件。导入走强制安全体检
（提示注入/破坏性命令/捆绑脚本扫描），通过后自动启用，进入
渐进披露目录（系统提示只注入名称+描述，模型按需 `util.loadSkill` 加载全文）。

技能内容为核心工作流纪律：**快照（snapshot）→ ref 定位 → 操作 → 截图仅作
视觉留证**，以及多标签/对话框处理与排障顺序。

## 五、验收链路

配置启用后，给 Agent 发：

> 打开 https://example.com ，告诉我页面标题和正文大意，并截图留证。

预期行为：`browser_navigate` → `browser_snapshot`（读结构）→ 回答内容 →
`browser_take_screenshot` 一次。若 Agent 只截图不快照，说明技能未加载，
检查技能启用状态与 `util.loadSkill` 可用性。

## 六、安全边界（部署须知）

| 面向 | 事实 |
|---|---|
| 执行位置 | 浏览器子进程运行在 Agent 服务主机，以服务进程权限访问网络 |
| `--blocked-origins` | 官方明示**不是安全边界**（不影响重定向）；作为纵深一层，不能替代网络隔离 |
| 文件系统 | 默认限定工作区根目录，`file://` 导航被禁用；`--allow-unrestricted-file-access` 不要开启 |
| SSRF 覆盖差集 | Lumina `util.http` 的 SSRF 防护**不覆盖** MCP 工具发起的浏览器流量 |
| 隔离建议 | 生产环境将 Agent 服务（连同浏览器）部署在独立主机/容器/网段，出口走代理 |

## 七、Token 成本控制（与批次 1.3 衔接）

快照与截图都会进入模型上下文。两个开关：

- `--image-responses=omit`：页面响应中的图片不回传模型（文本快照不受影响）；
- 技能纪律本身要求"快照优先、截图仅留证"，已把视觉 token 压到最低必要。

## 八、常见问题

- **启动失败 `browserType.launch`**：内核未安装，回前置条件第 2 步。
- **`--blocked-origins` 拦截了业务站点**：检查通配写法，站点在名单内移除即可。
- **健康检查显示 DISCONNECTED**：看 Agent 服务日志 MCP 段；npx 首次拉包慢，
  可预热（手动跑一次 `npx -y @playwright/mcp@latest --version`）或改用
  固定安装（`command: node`，args 指向全局安装的入口脚本）。
